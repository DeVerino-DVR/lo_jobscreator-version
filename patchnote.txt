<patchnote>
1.1.0
- Feat: Config.BlipGrouping.enabled toggle. The script's town-leader blips (registered for RDR2-native zoom-out clustering: blips marked BLIP_MODIFIER_GROUPING_<TOWN>_FOLLOWER collapse under their town leader when the player zooms out on the map) can now be disabled in one line if the server owner doesn't want them. Defaults to enabled — no behavior change for existing setups.

1.0.9
- Feat: built-in boss/gang menu fallback. When lo_bossmenu or lo_gangmenu are not installed, lo_jobscreator now serves a built-in society menu (hire, fire, grade update, deposit/withdraw, stash). Works for both jobs and gangs, supports VORP and RSGCore. Uses the new lo_society_accounts SQL table (auto-created).
- Fix: paycheck no longer silently swallows salary if lo_bossmenu/lo_gangmenu/lo_banking are not running. Boss/gang accounts now fall back to the built-in account system; banking falls back to cash (currencyType 0).

1.0.8
- Feat: Items tab enabled for RSG (ox_inventory + rsg-inventory). Create, update and delete items via config files (ox_inventory/data/items.lua for lo_core, rsg-core/shared/items.lua for vanilla RSGCore). Changes are injected into core.Shared.Items at runtime without restart.
- Fix: items list — removed the 200-entry display cap, all items are now visible.
- Fix: overly verbose setting hints — progress provider hint shortened, incorrect "Requires jo_libs" removed from gizmo placement hint.
- Feat: blip locales — style, color and modifier labels/descriptions now translated via locale files (9 languages).
- Feat: progress style selector (auto/ox_lib/vorp/native) with locales.

1.0.7
- Fix: target-prompt peds now use a softer pacification combo (SetPedFleeAttributes / SetPedCombatAttributes 46 / SetPedRelationshipGroupHash CIVMALE / SetPedKeepTask) instead of the heavy AI-blocking flags. They still won't flee, fight or wander, but remain valid lock-on targets. SetEntityInvincible + SetPedCanRagdoll(false) + SetEntityAsMissionEntity are kept so the ped still can't be killed or garbage-collected.
- Feat: target-prompt activation distance. The right-click prompt now reuses the interaction's `promptDistance` field (Server Config → Interactions) as the max distance for the prompt to be usable. Lock-on from beyond that distance only highlights the ped — the prompt itself is hidden until the player gets closer. Falls back to Config.PromptDistance, then 5.0 m.

1.0.6
- Fix: right-click target prompt on peds. Two distinct issues were preventing it from working: (1) the spawn-time AI-blocking flags (SetBlockingOfNonTemporaryEvents + ped config flags 517/230 + 0xBA0A9EAD3B3A0368) were also re-applied every 500ms by the maintenance thread, which makes RDR2's targeting engine treat the ped as static decoration and refuse the lock-on; and (2) the prompt was bound to INPUT_INTERACT_ANIMAL (G context), which the engine only lights up in normal context, never during lock-on. Target-prompt peds are now exempted from the AI-blocking flags (still kept invincible + mission entity + no ragdoll) and the prompt is now bound to INPUT_LOCKED_ON_DEFAULT_ACTION (0xE3BF959B), the input the engine activates specifically while the player has a target locked on.

1.0.5
- Feat: per-ped right-click target prompt (RDR2 native lock-on). Each ped interaction now has a "Right-click target prompt" checkbox in the editor — when ticked, the action is triggered by right-clicking the ped (aim/target) instead of getting close + pressing G. Self-contained: no external resource dependency. The proximity prompt is automatically suppressed when the target prompt is enabled, so players don't get both at the same time.

1.0.4
- Fix: consumable items created in the admin panel (tonic, food, drinks...) had their stat modifiers (healthCore, hunger, thirst, stress) silently ignored. The panel was sending empty strings for blank prop/animDict fields, which `completeItemData` treated as "already set" (`''` is truthy in Lua) so the type defaults were never applied. `createPropWithAnimation` then hung on an empty model/dict and `applyStatModifiers` was never reached. Empty fields are now correctly recognised as "use the type default", and the prop/dict loaders have timeouts to bail cleanly if something is wrong.

1.0.3
- Fix: revive — camera no longer stays stuck in death-cam position. The script now delegates to vorp_core's Player.Revive when vorp_core is present (proper SET_CINEMATIC_MODE_ACTIVE off + EndDeathCam + HUD restore). Built-in fallback also cleans the cam (DestroyAllCams + RenderScriptCams off + fade-in) for servers without vorp_core.
- Feat: applier animations + item gate for revive / heal / handcuff. Each action can require an inventory item (medkit, bandage, handcuffs...) and play a RedM scenario (or custom anim dict/clip) on the player performing it. All editable from the admin panel: Server Config → Actions → "Animation & Item".
- Feat: client-side hook `OnApplierAnim_<action>(cfg)` in modules/editable/client.lua for full takeover of the animation flow (return true to skip the default).
- Soft-load ox_lib: lo_jobscreator now auto-loads `@ox_lib/init.lua` at runtime when ox_lib is started, without declaring it as a manifest dependency — buyers without ox_lib see no errors, servers with it get the global `lib` automatically.

1.0.2
- Fix: item creator — `lo_item_usables` is now only written when the item is both Usable AND Consumable (otherwise the row is removed on create and update), preventing stray inserts for plain items
</patchnote>
